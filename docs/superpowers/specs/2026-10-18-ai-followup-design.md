# 局内 AI 追问设计方案（已确认）

日期：2026-10-18

开发基准：`dev`，当前提交 `d265164`。本稿只定义方案，尚未开始功能开发。

需求来源：[GitHub issue #1](https://github.com/Bertramoon/Guangdong-Mahjong-Training-Assistant/issues/1) 及本次会话已确认的需求。

## 一、给用户确认的重点

在现有「AI 分析」中增加提问和连续追问，让玩家能比较不同出牌的依据。

1. 保留「分析当前牌面」，也允许直接输入问题；继续复用已有模型设置。
2. 比较两张出牌时，展示双方向听数、有效进张牌种、共有牌种与各自独有牌种。
3. 数字和牌种来自本地计算；AI 按需解释，不独立建设手牌结构分解或胡牌路线推演功能。
4. 一段追问始终讨论同一局面。牌局变化后提示正在讨论此前局面，用户主动切换到当前牌面。
5. 首版集中于玩家出牌阶段；新游戏或刷新后清空讨论，不建设跨局历史功能。

## 二、已确认的目标与范围

### 用户目标

帮助练习者回答「为什么这样打」「换一种打法会失去或增加哪些机会」，从接受推荐进一步学习比较。

### 已确认需求

- R1：现有 AI 分析区内的自然语言入口，支持直接提问。
- R2：同一局面的连续追问，能承接「那另一张呢」等指代。
- R3：自动携带提问对应的可见局面与本地算法依据。
- R4：比较任意两种合法出牌，包括当前 TOP10 外的出牌。
- R5：本地计算并展示两方案的确定结果及集合差异。
- R7：本地计算提供数值和牌种，AI 负责解释；按需回答结构问题，未经计算的路线只能表述为可能性。
- R8：请求中、取消、失败重试、输入保留、并发和上下文长度控制。

R6 已取消为独立需求，其按需解释能力合并到 R7。首版不要求每次回答都展开搭子、对子和胡牌路线。

### 首版边界

- 新建追问讨论限于玩家自己的出牌决策；已有的单次分析与碰杠分析能力保留。
- 讨论建立后允许继续讨论旧局面，即使当前已不在出牌阶段。
- 不增加碰杠连续教学、多步胜率预测、可见剩余张数计算、完整结构分解或跨局学习档案。
- 保持单局、纯前端的产品形态，无新增账号、服务端或模型配置入口。

## 三、用户如何使用

### 入口与内容顺序

继续使用现有信息抽屉的「AI 分析」标签，不新增顶层页面。

从上到下：

1. 正在讨论的局面标识（轮次、自己的手牌摘要、是否为此前局面）和「分析当前牌面」。
2. 现有推荐结果；发生比较时插入可核对的本地对比结果。
3. 问答记录。
4. 有明确标签的提问输入框、发送按钮；请求期间提供取消。

本地对比结果在窄面板按两方案分块显示，避免横向宽表。问答区域滚动，不拉高牌桌；沿用现有玻璃面板、中文字体、按钮和色彩 token。输入时不能触发牌桌的出牌快捷键；中文输入法确认候选词不触发发送。

### 典型流程

- 玩家可以先点击「分析当前牌面」，再问「为什么不打四筒」。系统使用这次推荐对应的快照，并记住推荐对象。
- 玩家也可以直接问「打七条和打四筒有什么区别」。系统固定当前局面，准备本地依据后回答，不要求先完成一次通用 AI 分析。
- 之后追问「共有的有哪些」「那种打法更容易听牌呢」，继续引用该快照和之前已明确的比较对象。
- 不能明确解析的指代或牌名，由 AI 简短澄清，不能默认猜成某张牌后输出精确比较。

快捷提问作为轻量辅助：「为什么推荐这张？」「和另一张相比呢？」「有哪些有效进张？」。快捷项只填入输入框，用户发送后才请求；没有推荐对象时不展示依赖推荐对象的快捷项。

## 四、局面与会话规则

### 固定与切换

- 手动分析或首次直接提问时捕获不可变局面；本地建议必须与这份快照一致。
- 同一讨论不随实时手牌变化而更新上下文，后续问题中的「当前」默认指面板标示的讨论局面。
- 局面改变后，显示「正在讨论此前局面」和对应手牌摘要，仍允许继续追问。
- 点击「分析当前牌面」是切换动作：取消旧请求，替换为当前快照，清空旧讨论并生成新分析。按钮旁明确说明会开启新讨论；不额外弹确认框。
- 新游戏、重播或页面刷新清空讨论。切换抽屉标签、收起面板保留讨论及输入。
- 旧局面晚返回的结果、取消后的结果和上一局的结果均不能覆盖当前显示。

### 自动分析兼容

用户尚未开始追问时，自动分析继续按现有开关跟随新出牌局面；用户发送首个问题（含待完成请求）后，该讨论固定，自动分析不再替换它。用户切换到当前牌面后重新开始；新游戏恢复默认行为。

### 会话保留与长度

仅在当前页面内存中保存单个讨论；不落入 localStorage，也不发送到额外服务。提供「重新讨论此局面」操作以清空问答并保留快照。

设计默认：单次问题最多 1000 个字符，每个讨论最多 20 轮成功问答。达到上限时保留已有内容，提示重新讨论；不静默丢弃历史导致指代失效。失败和取消不计入成功轮数。这些限额是设计选择，并非用户此前指定。

## 五、本地依据与 AI 的分工

### 对比结果

同一快照内，对每个被比较的合法弃牌取得：打出后的向听数、有效进张牌种列表。用程序计算共有牌种、A 独有牌种、B 独有牌种。

候选以牌种去重；鬼牌不作为合法出牌；不在手牌中的牌不能作为真实弃牌方案。TOP10 外的合法候选按需补算，而不是让 AI 推断数值。牌名识别或受限意图提取的实现方法留给开发者，但识别结果必须先通过本地合法性检查。

问答提出比较请求时，先识别并确认比较对象，再准备本地证据，最后形成回答。不得让模型在缺少该候选计算结果时先给精确数字。

### 口径

统一使用「有效进张：N 种」，明确标注「未扣除可见牌」。定义为：按当前本地算法，摸入后能降低向听数的牌种数。

相关出牌建议界面和 AI 上下文保持同一口径，纠正「进账」等易混淆用词。它不等于剩余牌张数、真实牌墙库存或摸牌概率；`maxCount=4` 不作为实际剩余数量展示。

「6 种对 5 种」不能简化为只有一种差异，必须实际计算交集和双方差集。用户引述的数量与本地结果不符时，先说明当前口径下的结果，再解释。

### 回答原则

- 普通问题优先直接回答，不强制每次输出完整对比模板。
- 两方案比较优先提供结论和可核对的本地对比结果，再解释最相关的差异；无需用户再问一次才列出双方进张。
- 数值和牌种以本地展示为准，模型不得修改这些字段；AI 文字必须依据同一份证据。
- 结构和路线只在用户追问或解释确有必要时涉及；没有验证的路线用可能性描述，不制造精确胜率、固定后续摸牌或额外计算结论。
- 不将结构解释的正确性寄托于新建完整分解引擎。AI 解释仍可能出错；确定数据独立展示，使用户能够核对，不能宣称解释完全无误。
- 遵循项目广东推倒胡规则，尤其是不吃、只自摸和鬼牌规则，不能引入放铳防守等其他玩法概念。

### 信息边界

发送自己的手牌、玩家可见的副露和弃牌、鬼牌、阶段、轮次、牌墙剩余数量及相关本地结果。

首版统一使用正常玩家视角；即使开启机器人明牌，也不额外发送对手暗手。牌墙内容、未来摸牌顺序、用于重建牌序的种子和完整内部 GameState 不发送。对手暗杠等信息依照真实可见范围处理。继续使用现有可信端点配置与说明。

## 六、异常与恢复

| 情况 | 产品行为 |
| --- | --- |
| 本地计算尚未完成 | 显示准备依据，等待同一快照结果后请求；失败时保留问题并允许重试 |
| 未配置可用 AI 服务 | 保留输入，引导打开现有设置；本地建议和游戏正常使用 |
| 请求中 | 同一时刻一个请求，禁止重复发送，允许取消，游戏操作不被锁定 |
| 请求失败 | 就地说明错误，保留已成功消息和本次问题，允许重试，不新增重复问题 |
| 用户取消 | 保留本次问题为可编辑草稿，不把半成品当成成功回答 |
| 本地比较成功但 AI 失败 | 已计算的对比结果仍可查看；解释部分显示失败与重试 |
| 牌名不明确或方案不合法 | 简短指出原因并澄清，不编造候选结果 |
| 单次输入或讨论超过限制 | 明确提示对应限制与处理入口，不自动清空 |
| 手机上键盘展开或内容过长 | 输入和发送可见，长内容在面板内滚动，不破坏牌桌和其他标签 |

## 七、验收重点

1. 能直接提问、承接已有推荐追问，且「那另一张呢」使用正确对象。
2. 两个合法出牌的向听数、进张牌种、交集与双方差集与同快照本地计算完全一致，覆盖 TOP10 外的候选。
3. 明确区分有效牌种数与剩余张数；用户给错数字时使用本地结果纠正。
4. 有鬼牌、副露和不同玩家阶段时，不混用实时局面与冻结局面；不发送隐藏信息。
5. 牌局推进、切换局面、新游戏、取消及请求乱序均不会将旧回答放入新讨论。
6. 自动分析不会打断用户已经开始的追问。
7. 失败重试保留上下文和问题，不重复提交；本地对比成功不依赖 AI 服务可用。
8. 桌面和 Android 横屏下能阅读、输入、取消和重试；中文输入法和牌桌快捷键互不干扰。
